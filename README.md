## 上一次更新：房間資料永久保存（Upstash）
- **解決**：更新 GitHub（Render 重新部署）、Render 休眠、伺服器重開時，所有房間與計時被清空的問題。
- 設定好 Upstash 後，會保存：房間、所有 CH 計時、自訂分頁、隊長、禁止名單（管理者與隊長）、移除名單、最近 200 筆操作紀錄。
- 伺服器重新啟動時自動讀回；關機期間時間照樣在走，讀回時會依現在時間重新計算每個 CH 的狀態（過期的恢復待機）。
- 預設王的名稱、時間範圍、順序以「目前程式」為準，所以之後改王的設定也會套用到舊房間。
- 房間有變動時，3 秒內的多次變動合併成一次寫入（節省 Upstash 免費額度）；Render 關機前會先把還沒存的資料寫完。
- **沒設定 Upstash 時，網站照舊運作**（只是資料只存在記憶體）；Upstash 連不上或密碼錯誤也不會讓網站壞掉，只會在 Render 的 Logs 顯示錯誤。
- 程式在 `persist.js`（伺服器端，不會傳給瀏覽器）。`package.json` 加上 Node 18 以上的需求（Render 預設版本即符合）。

### Upstash 設定步驟
1. 到 https://upstash.com 註冊／登入（可以用 GitHub 或 Google 帳號），免費方案不用信用卡。
2. 在 Console 建立一個 Redis 資料庫：名稱隨意（例如 `msctimer`），區域選離你的 Render 服務最近的（例如 Render 在新加坡就選新加坡），方案選 Free。
3. 進入資料庫頁面，在 **REST API / Connect** 區塊複製兩個值：`UPSTASH_REDIS_REST_URL`（網址，https://xxxx.upstash.io）與 `UPSTASH_REDIS_REST_TOKEN`（一長串 token）。
4. 到 Render → 你的服務 → **Environment**，新增兩個環境變數：
   - `UPSTASH_REDIS_REST_URL` = 第 3 步的網址
   - `UPSTASH_REDIS_REST_TOKEN` = 第 3 步的 token
5. 儲存後 Render 會重新部署。到 Render 的 **Logs** 看到「[保存] 已啟用 Upstash」與「[保存] 已從 Upstash 讀回 N 間房間」就代表成功。

> Token 等同資料庫密碼，不要放進 GitHub 或分享給別人，只放在 Render 的環境變數裡。

## 上一次更新：流量優化（只送有變動的 CH）
- **原本**：任何人點一次 CH（或 CH 自動變色），伺服器都會把整間房間的完整狀態（10 隻王 × 60 個 CH，約 52KB）送給房間裡每個人，這是 WebSocket 流量的主要來源。
- **現在**：點 CH、擊殺、回報死亡／重生時間、自動轉換狀態時，只送有變動的那幾個 CH（每次約 170 bytes，約小 300 倍）；同一秒內有多個 CH 同時變色會合併成一則訊息。
- 進入房間、斷線重連時仍會送一次完整狀態；新增／刪除分頁、改分頁名稱、改時間範圍這類少見操作也照舊送完整狀態，所以不會漏資料。
- 另外開啟 WebSocket 壓縮（只壓縮 1KB 以上的訊息，例如進房時的完整狀態）。
- 畫面與功能完全不變。Render 免費方案每月對外流量上限 5GB（HTTP 與 WebSocket 都算），超過且沒綁付款方式會停到下個月；優化後 WebSocket 流量預計降到原本的百分之幾。

### 大更新：子母畫面（Picture-in-Picture）
- 右上角新增「📺 子母畫面」按鈕，點下去會開啟一個**真正浮動在螢幕最上層**的小視窗（使用瀏覽器的 Document Picture-in-Picture API），切到遊戲或其他視窗時它仍然會留在最上面。
- 視窗初始的長寬比，是依照你點擊當下「進行中頻道＋操作紀錄」整個右欄的長寬比例去計算的。
- 子母畫面裡面包含：王（分頁）選擇列、完整的 60 個 CH 按鈕（左鍵開始/停止、右鍵回報死亡時間都可以用）、以及「進行中頻道」（倒數中／出現中，含擊殺按鈕），所有資料都跟主視窗即時同步，兩邊點擊也會互相反映。
- 目前子母畫面沒有放「操作紀錄」跟「管理者面板」，保持視窗單純精簡；如果你希望也能在子母畫面操作這兩塊，跟我說一聲即可加上。
- **瀏覽器支援度**：這個 API 目前只有電腦版 Chrome / Edge（116 以上）支援，手機瀏覽器跟 Safari、Firefox 都還不支援；不支援的瀏覽器點下去會顯示提示訊息，不會造成錯誤。

### 2. 右鍵功能改成回報「死亡時間」
右鍵輸入的不再是未來的目標時刻，而是**王被擊殺的時間**（一定是過去式）：

- 右鍵 CH → 彈出視窗只有一個時間選擇欄位，預設帶入「現在」（代表王剛剛才死）
- 輸入的時刻若還沒到（例如現在 23:56，輸入 22:30，22:30 已經過了沒問題；但如果輸入 23:59 就會比現在晚），系統會自動視為**昨天的這個時間**，因為死亡時間不可能在未來
- 儲存後，系統會把這個死亡時間當作起算點，套用分頁原本的最小值/最大值自動計算：到「死亡時間 + 最小值」會進入「出現中」提醒，到「死亡時間 + 最大值」會重置回待機。如果輸入的死亡時間本來就已經超過最大值，存檔後會立刻被判定為已經重置（回到待機）
- 這個動作**一定會覆蓋**該 CH 目前的狀態（不管原本是待機、倒數中還是出現中），適合用來事後更正錯誤的擊殺時間
- 原本「還原為分頁預設」按鈕改成「恢復待機」，作用等同左鍵手動停止：清空這個 CH，回到沒有人倒數的狀態

### 3. 管理者可以刪除操作紀錄
- 每一筆紀錄右側會出現一個「✕」（只有管理者看得到），可以單獨刪除那一筆
- 操作紀錄面板標題旁新增「清空紀錄」按鈕（同樣只有管理者看得到），可以一次清空全部紀錄
- 清空紀錄這個動作本身會留下一筆新紀錄「管理者清空了所有操作紀錄」，讓大家知道紀錄被清過，避免誤會
